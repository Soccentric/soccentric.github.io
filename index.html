Engineering notes

Three decisions behind the platforms, and why they were made that way.

One architecture, ten processor families

Every Linux platform has the same eleven repositories in the same roles, and every OS repository answers the same commands: make image, make sdk, make shell, make flash, each taking a board name. WebConfig is one codebase on all nine; a board is just a manifest plus its Yocto machine binding. Moving a product to another SoC changes the board layer, not the workflow.

  • Same repo layout and roles on every platform
  • One Makefile interface across nine OS builds
  • Board differences live in manifests and BSP layers

Updates that cannot brick a microcontroller

Lyra's bootloader keeps two application slots (976 KB each on the reference STM32F767ZI). An update is checked against an ECDSA P-256 signature before anything is erased, and again on every boot. A new image boots on trial under a watchdog and must confirm itself; three failed starts roll back to the last good slot. An anti-rollback counter blocks downgrades without burning OTP or option bytes, all in about 28 KB.

  • Verify before erase, verify on every boot
  • Trial boot with automatic rollback
  • Anti-rollback without one-time-programmable writes

Validation that runs on top of production

The Validation & Verification layer never replaces the shipping stack; it rides on it. A gRPC daemon on the device exposes the HAL, sequences test runs and spools results locally so they survive network drops. The server streams to devices with heartbeats and backpressure, and the dashboard follows runs live. You test the image you ship.

  • Device-side daemon exposes the HAL over gRPC
  • Durable local spool survives disconnects
  • Streams with heartbeats and backpressure
